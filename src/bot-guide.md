# Plus One: product knowledge

This is application knowledge, not Telegram conversation content. Explain it in
the active profile's language. Actual runtime capabilities and permissions take
precedence over a general description. Never claim an external action succeeded
without its actual result.

## Installation

The installation agent first asks where and how to run the bot (local Docker,
VPS Docker, or a documented native setup). It installs dependencies, then asks
for Codex CLI or the existing Anthropic API-key/Claude CLI connection. Verify AI
before requesting Telegram credentials. Next provide ONE complete Telegram
checklist: create through BotFather, allow groups, disable Group Privacy, obtain
the human owner's numeric account ID and supply it with the token once. Store both
privately; correct only the failed item on verification. A username alone never grants ownership. Verify connections
before starting one poller per token. End with the bot's private Start link.

## Personalities and groups

A profile defines name, personality and language. Create several and reuse one in
several groups. Features are configured for a specific joined group, never in a
saved personality. Changing personality preserves feature settings, players,
rules, pack, history and memory. Editing a shared profile updates linked
personalities after an explicit preview of affected groups. A deliberate
owner-only character rule may override the assigned personality. Do not claim
multiple simultaneously active personalities per group.

The owner's first private /start asks their preferred name and the bot's name in
English operator style, then language, then character in that language. These
three questions have no Back/Cancel. Preview has Save profile/Edit; Edit opens
name/character/language, retains other fields and returns to full preview. Only
Save commits. New profile title matches the bot's name; legacy labels remain.
The owner preferred name is separate private context, never part of profiles or
group prompts and never authorization. Automatic conversation language follows
the speaker; setup UI follows the owner's supported Telegram account language.
After save show the concise approved introduction with Add to group/View features;
the catalogue is separate. Questions/help are available before adding a group. Feature editing
requires a selected joined group, assigned profile and bot administrator rights.
After joining, privately notify the owner with the actual group name and profile
choices. If admin rights are missing, show the named-group Check rights action.
After assignment show a flat list of14 group functions with direct buttons and
their current state. Distinguish missing setup, unavailable connection and a known
failed attempt. Already configured off remains off. Status is read-only available.
Use group names; optional private menu labels distinguish duplicate names.
Failure to deliver
a notification does not erase the discovered group. /setup reopens settings.
Only the configured installation owner may view or edit private configuration;
being a Telegram group administrator does not grant installation ownership.

## Defaults and voice

New configured groups enable addressed conversation, research, judging and history;
long-term notes are saved only on explicit /remember, /memory or /forget requests.
Received history is retained for seven days with group/topic boundaries. It is not
an automatic import of older Telegram messages or another group's memory.

All received eligible group voices are transcribed and recorded in group history
for context. Ordinary voices get no response. Answer only a valid addressed
request, permitted command/rule or reply to this bot. Apply the same actor,
forward, quote and replay checks as text. There is no reply-to-all voice setting.
History transcripts are not automatically permanent facts. File, processing and
configured duration limits and failed transcription can make some audio
unavailable: disclose that rather than pretending to know its contents.

Photo/video analysis is enabled but performed only on request. Video analysis
uses sampled frames and recognized speech, not a complete audiovisual viewing.
Automatic public-link downloads are enabled for new configured groups: supported
Instagram, Threads and TikTok URLs, bot administrator rights and installed tools
are required. Private posts, login requirements, site blocks, quotas and file
limits can prevent downloading. Previously saved disabled settings stay disabled.

## Additional setup

Game calls: describe any game this group plays, @usernames, optional GIF and caption.
Explicitly ask what to call its command unless the owner already supplied that
name. There is no required preset game catalogue. Ask only missing details, offer
optional launch phrases and actor/matching choices, then privately preview/save.
Each group has its own commands and players. Corrections retain the same command
identity; phrase actions reference it, never copy its payload. The picker, manual
/assemble command and explicit bot requests use this record. Casual game names
do not summon anyone without a saved enabled phrase rule. Calling
everyone needs a complete verified member roster; the bot cannot enumerate all
unseen existing members. A configuration preview must not summon anyone.

Phrase actions: one or more alternative phrases, whole-message or contains-whole-
words matching, a bounded action (judge, saved gathering, GIF, message, personality),
permitted actor and optional announcement, then preview/save. Optional phrases
added within gathering/judging setup appear in this same list. Disabled/deleted
gatherings and disabled judging cannot execute dependent rules.
Personality actions are owner-only. Quotes, forwards and code cannot trigger rules.

Sticker packs: connect an existing regular pack editable by this bot, or create
one from a title, prepared first image and emoji after a private preview and
explicit Create. Creation recovers the same journalled pack after interruption;
never create duplicates or connect an unrelated set. One active group per pack.
Group administrators may add/remove individual stickers; whole-pack deletion is
not offered.

Moderation: select permitted group administrators, review, then enable. The bot
also needs permission to restrict members. Use /kick by reply or a known recent
username. Do not remove group owners/administrators. Owner identity, group-admin
status and action authorization are separate checks.

Mini Apps (Duel, Flappy Bird, Occupiers) are off initially and require their own
services, reachable public HTTPS addresses, BotFather registration and the chosen
game's public IDs/room or record state. Explain requirements inline to a
nontechnical owner and give a copyable request to their installation agent, rather
than requiring a technical document. Reuse suitable hosting/addresses and discuss
costs before purchases. A local page alone is insufficient for Telegram users. Never put
the bot token in a game client. Connecting a game does not automatically enable
it in every group.

## Controls and limits

Use buttons for navigation, switches and choices, and messages for user-supplied
data/files. Complex setup is a guided conversation, with multiple fields per
message, out-of-order answers and natural corrections. Explain the feature first,
ask only missing fields and return from help to the pending detail. Explain
testing with actual saved group/command/phrase and expected effect. No action in
the group runs from help or preview. GIF previews are real private sends; native
animations reuse their ID, GIF documents/short videos are prepared/uploaded as
animation. Failed files retain the draft and offer replacement/optional skip.
Scope every operation to its named group. Disabling retains saved parameters.
Direct All features opens an unsaved-change recovery prompt; explicit cancel
discards only the draft. After save ask naturally if anything should change;
corrections reopen the same item, and Done returns to the group overview. Open menus
do not consume unrelated conversation. Stale buttons must not save old previews
or act on a newly selected group. /ping checks availability; owner-only /status
reports dependencies. An enabled preference is not a successful external test.

Codex provides the maintained independent connection. The current Claude adapter
supports text conversation, profiles and classification; image input, live web
search and the scoped history tool are not wired to it. Do not promise parity.
Never invent unknown settings, connections, secrets or successful delivery.
# Research and media follow-ups

For current facts, perform real research and cite the supporting pages. A limited
direct connection to a supplementary site does not mean no information was found;
explain the actual gap. Recent research evidence supplied by the transport can be
reused only for the same task and listed sources; requested updates need new search.

Media progress distinguishes retrieval, preparation and sending. An unconfirmed
send may already have appeared: do not claim definite failure or automatically
duplicate it. The user can check the chat and explicitly request another send.
Prepared-file retries and partial albums use the existing operation/cache state.
Some Threads pages omit post content from their server response; this restriction
does not establish that the media format is unsupported or the post is private.
